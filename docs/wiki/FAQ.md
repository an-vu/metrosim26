# FAQ

## What decides where buildings go?

- **OpenStreetMap:** existing buildings, roads, land use, water, parks, and nearby places.
- **Census LODES:** workplace jobs and jobs linked to workers' home locations.
- Home-location job counts are **not population or household counts**.
- Missing building heights and some uses are estimated.
- The starting label is 2026; the inputs are not all observations from 2026. LODES defaults to 2023.

The model estimates demand, then develops in this order:

1. **Infill:** use available space in developed areas.
2. **Redevelopment:** replace eligible buildings generated by the model, usually after 12 years.
3. **Expansion:** grow into nearby areas with road access.

- Existing mapped buildings stay protected.
- Road access, nearby development, housing/jobs, and centrality help rank locations.
- Footprints are checked against buildings, road buffers, water, parks, and boundaries.
- Building types follow demand and location rules. High-rises need stronger centrality and demand.
- The seed varies layouts and heights reproducibly; it does not scatter buildings anywhere.

## Is this a prediction?

- It is a **possible city-growth scenario**.
- Default annual growth is **0.8% for households** and **1% for jobs**.
- Spare capacity is used first. Unmet demand carries into later years.
- Zoning decisions, ownership, prices, utilities, terrain, and budgets are not modeled.
- Matching inputs, settings, and numerical environment produce repeatable results.

## Is Blender stuck?

- Watch **N → MetroSim26** for the phase, year, and mesh progress.
- Data preparation can take a while before the first simulated year appears.
- Calculations run outside Blender. Scene import happens in small chunks.
- Native mesh updates, saving, or rendering can still briefly pause the interface.
- An advancing year, mesh count, or log shows progress.
- A heartbeat only shows the reporter is alive; it does not prove the calculation is advancing.
- If nothing advances for much longer than similar runs, check the job's `calculation.log` and Python CPU/disk activity.

Useful log messages:

- **`OSM` / `LODES`:** reading the cached inputs.
- **`Baseline`:** the starting city is prepared.
- **`Year ...`:** simulating growth.
- **`importing ...`:** adding geometry to Blender.
- **`Ready`:** the scene is complete.
- **`Pool not started`:** the workload did not need workers.
- **`SERIAL FALLBACK`:** worker startup failed; calculation continues without the pool.

## How do I watch the console log?

Run `live_logger.py` before `blender.py`. Then use a separate terminal:

**Windows — PowerShell**

```powershell
Get-Content "$HOME\Documents\Blender_Logs\blender_live_console.log" -Wait -Tail 30
```

**macOS — Terminal**

```sh
tail -n 30 -f ~/Documents/Blender_Logs/blender_live_console.log
```

- Press **Ctrl+C** to stop watching.
- Restarting the logger resets this log.
- The job's `calculation.log` is available even without the optional logger.

## Why isn't CPU, GPU, or RAM usage at 100%?

- **CPU:** data preparation and some simulation steps run serially. Workers help with building-layout planning.
- **Workers:** `CPU_WORKERS` is a maximum. Small batches may use fewer workers or none.
- **GPU:** the simulation does not use it for calculation. GPU rendering is separate.
- **Windows rendering:** the code tries OptiX, then falls back to CPU.
- **Mac rendering:** the code falls back to CPU; it does not configure Metal.
- **RAM:** the model uses what it needs. Workers share read-only mapped inputs.
- **Network:** downloading happens before Blender runs. The launcher forces offline data loading.

## Can I cancel or resume?

- Use **Cancel Simulation** in the panel.
- Completed runs and input data are kept.
- Partially imported geometry is cleaned up.
- An interrupted simulation does **not** resume from its last year.
- Use `REPLAY` for a completed compatible run, or `SIMULATE` for a fresh one.
- Use `EXTEND` with `EXTEND_FROM` and a later `END_YEAR` to continue a **completed**
  run. Only the additional years are calculated. Blender imports a new full-timeline
  scene; existing scenes and source results are retained. This does not resume a
  cancelled partial run. See the README extension instructions.

## Can I move the folder or switch computers?

- Yes. Copy the whole repository and open its saved root `blender.py`.
- Both Windows and macOS use cache/output folders under your home `Documents` folder.
- Download data on the new computer, or copy the matching cache separately.
- For a custom `WORKER_PYTHON`, use an interpreter whose NumPy version matches Blender's.
- After the Urban Generator rename, prefetch again and run `SIMULATE`; older results do not automatically match the new identity.
